# 脚本目录

本文按使用场景整理 `scripts/`。实际参数以各脚本的 `--help` 和 DolphinScheduler 工作流定义为准。

## 日常数据同步

| 脚本 | 主要职责 |
|---|---|
| `销售单查询_web.py` | 滚动同步销售单主数据 |
| `销售单明细账_web.py` | 滚动同步销售商品明细 |
| `入库查询_web.py` | 同步采购入库主单、明细及品牌月度到货 |
| `渠道列表_web.py` | 同步渠道主数据快照 |
| `总库存查询_web.py` | 同步总库存快照 |
| `分仓库查询_web.py` | 同步分仓库存快照 |
| `批次货品库存查询_web.py` | 同步批次和效期库存 |
| `客户档案_web.py` | 同步客户档案 |
| `进口超市上海仓_正向全链路数据_web.py` | 同步进口超市上海仓正向履约链路 |
| `进口超市上海仓补全_web.py` | 构建货权采购金额映射和销售 DWD 补全 |
| `天猫国际自营金额补全.py` | 使用本地业务文件补全天猫国际自营金额 |
| `销售品牌补全.py` | 刷新品牌映射并回填销售品牌 |

## 调度、质量和发布

| 脚本 | 主要职责 |
|---|---|
| `吉客云同步预检.py` | 检查登录态文件和运行前置条件 |
| `配置海豚工作流.py` | 通过 DolphinScheduler API 幂等维护工作流定义 |
| `数据质量闸门.py` | 在 ADS 前执行时效、完整性和业务质量检查 |
| `等待ADS发布.py` | 轮询远端 ADS 销售和库存发布批次 |
| `sync_curl_auth.py` | 从一份最新 cURL 同步 token、cookie 等登录态 |

## 历史维护和回补

以下脚本不是默认日常入口，运行前应确认日期范围、数据库负载和可恢复性：

| 脚本 | 主要职责 |
|---|---|
| `历史库存_web.py` | 维护月末历史库存快照 |
| `销售历史归档回补.py` | 销售历史归档与回补 |
| `入库历史归档回补.py` | 入库历史归档与回补 |
| `销售2025回补合并.py` | 合并 2025 年销售回补结果 |
| `入库2025回补合并.py` | 合并 2025 年入库回补结果 |

## 辅助和报表

| 脚本 | 主要职责 |
|---|---|
| `warehouse_list.py` | 查询仓库编码 |
| `生成资生堂2025周转Excel.py` | 生成指定历史分析报表，结果写入已忽略的 `output/` |

## 维护约定

- 新的日常任务必须同时更新本文件、`README.md` 和 `配置海豚工作流.py`。
- 回补、实验或一次性报表脚本不得直接挂入每日主流程。
- cURL、业务 Excel、日志和生成结果只存在于运行环境，不能提交。
- 删除或替换旧入口时，在提交说明中明确迁移关系和回滚方式。
